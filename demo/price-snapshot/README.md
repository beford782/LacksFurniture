# Website price snapshot — UNVERIFIED, NON-SHIPPING

Generated by `tools/fetch_lacks_prices.py` on 2026-09-20.

## What this is, and what it is not

This directory holds **website-sourced prices pending owner verification**. It
exists to support step 3 of the agreed workflow:

```
website → automated extraction → reviewable snapshot → Blake verification → verified preview data
```

It is **not**:

- approved pricing,
- a production input,
- an authorization to activate anything.

`incoming/`, `data/`, the workbook and `store-config.json` are untouched by the
extractor and stay untouched by this directory. The pricing contract's
`sourcePolicy.status` remains `unapproved` and `pricing.enabled` /
`displayEnabled` remain `false` regardless of what is captured here. Verifying
the snapshot does **not** equal authorizing production pricing.

This directory sits beside the illustrative Black Friday demo under `demo/`
for the same reason that one does: `demo/` is the established location CI
treats as isolated from production, and the Daybreak contract check already
pins that demo content never reaches the production pipeline.

## The two traps this capture is built around

**1. `regular_price` is the crossed-out price.** `final_price_without_tax` is
the selling price. Most mattresses carry a final price well below their regular
price (Restonic Grace II King: final **$779.00**, regular $1,099.95). Reading
`regular_price` as the selling price would overstate nearly every mattress by
hundreds of dollars. The snapshot records both and labels only the first as the
selling price.

**2. A category page does not establish a size.** `king-mattresses` returned 23
King records and one Queen. Every variant is therefore filed under the size in
its *own* record, and `sizeSource` says whether that came from the record's
`mattress_size` field or was parsed from the displayed name. No size is ever
inferred from another size.

## Exceptions — 134 variants deliberately NOT treated as prices

| count | exception | why it is excluded |
|---|---|---|
| 69 | `configurable-parent-not-an-exact-variant` | a variant *parent*, whose displayed figure is a "starting at" price that changes with the page's size context. Needs a product-page drill to resolve per variant. |
| 59 | `name-suggests-a-set-not-mattress-only` | bed ensembles, comforter sets and similar. A set is not a mattress and must never be totalled as one. |
| 23 | `no-resolvable-size` | no size in the record or the name. Not guessed. |
| 7 | `quote-only-product` | `display_request_a_quote` is true — the site itself declines to publish a price. |
| 4 | `size-differs-from-category-*` | found in one size's category, carries another size. Filed under its own size and flagged. |

## What was deliberately not read

- **Stock and availability.** `stock_item.is_in_stock`, `location_inventory`
  and the `IN STOCK` product flag are all present and all ignored: availability
  is not inferred from a listing.
- **`poa`** — despite the name it is not "price on application"; its observed
  values are `''`, `'Low Stock'` and `'Product Coming Soon'`, i.e. stock state.

## Reproducing

```
python tools/fetch_lacks_prices.py
```

Paced at 8s between requests with 30/60/90s backoff on a 403. The site throttles
bursts: about ten rapid requests earns a 403 that clears within a minute. A
refusal is recorded as a category problem — it never becomes an invented price.

`/api/rest/*` still returns 403 to automated requests, matching the PerimeterX
note in `incoming/fetch_lacks_images.py`. The catalog **pages** are readable, so
the extractor reads the Next.js `__NEXT_DATA__` island rather than the API.
Pagination is `?page=N`; `?p=N`, `?curPage=N` and `?offset=N` all silently
re-serve page 1, which would have captured half the catalog while appearing to
succeed.
